# リッチ化スタイルガイド（P0: compare / review / age）

対象サイト: https://middle-engineer.com （30代・40代ITエンジニア特化の転職エージェント比較サイト「ミドルエンジニア転職ラボ」）

## 技術ルール

- Next.js 16 静的エクスポート（output: 'export'、trailingSlash: true）。**内部リンクは必ず末尾スラッシュ付き**（例: `/review/levtech/`）
- 既存ページを必ずRead してから書き換える。以下は**必ず維持**:
  - `export const metadata`（title/descriptionは検索意図に合わせ改善可。文字数: title 32字前後、description 110字前後）
  - `ArticleJsonLd`・FAQPage JSON-LD・`Breadcrumb` の使用
  - Tailwindクラスの既存トーン（slate基調+blue accent、`max-w-4xl mx-auto px-4 py-10` 等）
- 新規追加: `import DataNote from "@/components/DataNote";` を使い、H1直後の導入文の後に `<DataNote surveyedAt="2026年6月" sources={["..."]} />` を配置
- ページは `export default function XxxPage()` の単一コンポーネントのまま。クライアントコンポーネント化（"use client"）はしない
- データ量が多い場合はファイル冒頭で `const` 配列に分離し、JSXでmapする（既存ページの書き方に合わせる）

## コンテンツルール（competitor調査で判明した上位の必須条件）

1. **文字数**: 日本語テキスト実質10,000字前後（現状の3〜4倍）。水増しではなく情報密度で増やす
2. **結論ファースト**: H1直後に「結論」ボックス（比較ページなら「どっちがおすすめか」を即答+3行で理由）
3. **目次**: H2へのアンカーリンク目次を冒頭に置く（`<nav>` + `#` リンク、H2側に `id` 属性）
4. **比較表**: 運営会社/求人数(時点明記)/対応エリア/得意領域/年収アップ実績/サポート/料金 の統一フォーマット
5. **メリット・デメリット**: 両方を必ず。デメリットも具体的に（E-E-A-T: 公平性）
6. **口コミ**: 「Qiita Job Change・みん評等では〜という声」と出典名付き傾向要約。**架空口コミ・原文転載は禁止**
7. **向いている人/向いていない人チェックリスト**: ✓形式
8. **使い分け・併用ガイド**: 比較ページは「Aが向くケース/Bが向くケース/併用パターン」
9. **FAQ**: 6〜10問に拡充（検索サジェスト的な質問: 「断られる？」「しつこい？」「退会方法は？」等）。FAQPage JSON-LDも同期
10. **30代・40代視点**: 当サイトの読者はミドルエンジニア。必ず「30代・40代にとってどうか」の独自視点セクションを入れる（これが当サイトのInformation Gain）
11. **内部リンク**: 関連review/compare/age/knowledgeページへ文中リンク+末尾関連記事6本
12. **公的統計**: 年収・市場の話では厚労省job tag・経産省・doda/レバテック公表値を時点付きで引用（datasheet参照）
13. **更新日**: 「最終更新: 2026年6月」表記

## 禁止事項（絶対）

- 架空データ・架空口コミ・架空体験談・架空の取材談
- 「当サイト独自アンケート」への言及（実施していない）
- datasheetにない数値の創作。確認不可項目の断定
- 誇大表現（「絶対」「必ず受かる」等）、特定サービスの過度な貶め
- 料金・会社情報のdatasheetからの改変
